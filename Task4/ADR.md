# ADR — MVP. Передача депозитных ставок в кол-центр

**Автор:** Кулик Егор 
**Дата:** 8 февраля 2026

---

## Функциональные требования

1. Система должна обеспечивать доступ к актуальным депозитным ставкам для внутреннего кол-центра в режиме только для чтения.  
2. Система должна автоматически готовить и передавать файл со ставками для партнёрского кол-центра.  
3. Формат передаваемых данных должен быть унифицированным и широко поддерживаемым (CSV или Excel).  
4. Должна быть реализована настройка расписания обновления ставок (например, ночное обновление).  
5. В выгрузке должны содержаться: наименование продукта, срок размещения, процентная ставка, условия, а при наличии — ставки с учётом клиентских сегментов.

---

## Верхнеуровневые Use Cases

| № | Действующие лица / системы | Use Case | Описание |
|:-:|----------------------------|----------|----------|
| 1 | Клиент банка / Сотрудник кол-центра | Просмотр депозитных ставок | Клиент обращается в кол-центр, оператор открывает систему, получает актуальные ставки из бэк-офиса и использует их при консультации. |
| 2 | Бэк-офис депозитов / Партнёрский кол-центр | Передача ставок партнёру | Бэк-офис формирует файл со ставками и передаёт его партнёру по защищённому каналу для дальнейшего использования. |
| 3 | Менеджер бэк-офиса депозитов | Обновление ставок | Менеджер обновляет ставки во внутренней системе, после утверждения данные автоматически распространяются в кол-центры. |

---

## Нефункциональные требования

| № | Требование |
|:-:|------------|
| 1 | Передача файлов должна осуществляться по защищённым каналам (SFTP или защищённая почта). |
| 2 | Сервисы должны быть доступны 24/7 с SLA не ниже 99.9%. |

---

## Решение

Решение основано на необходимости обеспечить сотрудников кол-центров актуальными ставками с минимальными операционными рисками и без внедрения новых сложных интеграций.  
Для внутренних пользователей используется прямой доступ к данным бэк-офиса депозитов.  
Для партнёрских кол-центров реализуется файловый обмен в стандартных форматах через защищённые каналы связи с возможностью планового обновления.

---

## Альтернативы

**Прямой API для партнёрского кол-центра**

Не выбрано, так как реализация API потребовала бы дополнительных затрат, увеличения сроков разработки и изменений на стороне партнёра. В рамках MVP партнёр поддерживает только файловый обмен.

---

## Недостатки, ограничения и риски

**Недостатки и ограничения:**
- Возможны задержки обновления ставок при файловом обмене.
- Риск ошибок при ручной обработке файлов.
- Необходим дополнительный контроль передачи данных.

**Ограничения MVP:**
- Отсутствует прямая API-интеграция с партнёрским кол-центром.
- Расширенная автоматизация и интеграция с другими системами банка не входят в текущий объём.

**Риски безопасности:**
- Требуется шифрование файлов и защита каналов передачи.
- Контроль доступа сотрудников к данным.

**Ограничения технологического стека:**
- Используются только технологии, по которым имеется внутренняя экспертиза.
