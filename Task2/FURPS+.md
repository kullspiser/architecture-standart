# Требования к системе открытия депозитов

## F — Функциональные требования (Functionality)

| № | Требование                                                                                                                       | Комментарий                                                                                                                                                                |
|---|----------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| F1 | Клиент может просматривать список доступных депозитов c дополнительной информацией - актуальные ставки и его персональные ставки | Возможно стоить выделить момент нотификации пользователя об изменении ставок, чтоыб привлечь его открыть новый депозиит                                                    |
| F2 | Клиент может подать заявку на депозит, указав Ф.И.О. и номер телефона                                                            | Для новых клиентов, требует последующей идентификации. В дальнейшем возможна интеграция сторонней системы для автоматической идентификации по Face ID или номеру документа |
| F3 | Менеджер кол-центра обрабатывает заявки и может предложить персональные условия для клиента                                      |                                                                                                                                                                            |
| F4 | Клиент интернет-банка может подавать заявки с указанием счёта и суммы, подтверждая через СМС                                     | Требует интеграции с ядром СМС                                                                                                                                             |
| F5 | Клиент может просматривать список доступных депозитов c дополнительной информацией - актуальные ставки                           |                                                                                                                                                                            |

## U — Удобство использования (Usability)

| № | Требование | Комментарий              |
|---|------------|--------------------------|
| U1 | Интерфейс соответствует корпоративной системе дизайна | Требуется дизайн-система |

## R — Надёжность (Reliability)

| № | Требование | Комментарий                                                                                          |
|---|------------|------------------------------------------------------------------------------------------------------|
| R1 | Доступность сервисов 24/7, SLA ≥ 99.9% | Требуется налаженная работа SRE-отдела, возможно необходимо выделение отдельной команды обслуживания |
| R2 | Обработка заявок не должна напрямую нагружать АБС | БД АБС уже перегружена, рекомендуется избежать прямых обращений                                      |
| R3 | Возможность переключения на резервный ЦОД |                                                                                                      |

## P — Производительность (Performance)

| № | Требование | Комментарий |
|---|------------|-------------|
| P1 | Горизонтальное масштабирование серверов, ЦОД и приложений | |
| P2 | Минимизация времени отклика при загрузке справочников | |

## S — Поддерживаемость (Supportability)

| №  | Требование                                                                                         | Комментарий |
|----|----------------------------------------------------------------------------------------------------|-------------|
| S1 | Документирование процессов и API для дальнейшего расширения                                        | |
| S2 | Введение журналов ADR для понимания бизнес-потребностей и их реализации в долгосрочной перспективе |
| S3 | Введение журнала сбоев или инцидетов для понимания слабых мест системы и их устранения             |

## +R — Ограничения (Restrictions)

| №   | Ограничение                                                                         | Комментарий |
|-----|-------------------------------------------------------------------------------------|-------------|
| R+1 | Использование существующих технологий банка (MS SQL, Oracle)                        | Новые технологии должны быть совместимы с текущей инфраструктурой и доступной экспертизой |
| R+2 | Переход на микросервисную архитектуру в части открытия депозитов                    | |
| R+3 | Все критические данные должны быть зашифрованы                                      | |
| R+4 | Система должна пройти аудит по защите данных по актуальному законодательству страны | |
